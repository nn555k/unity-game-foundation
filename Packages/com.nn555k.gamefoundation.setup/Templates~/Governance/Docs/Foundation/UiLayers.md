# UI 分层规范 v1

状态：已采纳的可复用设计与验收契约，2026-10-22。适用于同一屏幕 UI 域内的 Unity uGUI；消费项目在自己的 `Docs/Foundation/UiLayers.Project.md` 中记录接入。本文定义职责与行为，不声明 Foundation 已提供同名运行时 API。

## 默认层级与选择规则

每个屏幕 UI 域由唯一分层根管理以下七个语义宿主，按表中顺序从后向前绘制。新项目使用默认排序值；既有项目可由分层根集中配置其他数值，但必须保持相对顺序，业务视图不能自行分配排序值。

| 宿主 | 默认顺序 | 职责 | 输入规则 |
| --- | ---: | --- | --- |
| Pages | 0 | 完整页面及其 HUD、局部内容 | 无更高门控时允许输入；页面可有独立 CanvasScaler |
| Panels | 100 | 页面浮层、非模态工具面板 | 始终在普通弹窗下方；受更高门控约束 |
| Popups | 200 | 需要关闭后返回来源的模态窗口 | 仅栈顶窗口接收输入；遮挡 Pages、Panels |
| Guides | 300 | 引导遮罩、手势、引导说明 | 装饰不拦截；交互引导显式登记门控 |
| Effects | 400 | 跨页面金币、道具等表现动画 | 永不接收或拦截输入 |
| Toasts | 500 | 临时通知、错误提示 | 永不接收或拦截输入 |
| Blockers | 600 | 加载、转场、全屏系统阻断 | 激活时显式门控全部低层，并提供全屏射线遮挡 |

- **按交互职责选层。** 商店作为主页面时属于 Pages，作为非模态页面浮层时属于 Panels，需要覆盖当前界面并返回时属于 Popups；不能仅按“商店”“背包”等业务名称决定层级。
- HUD 是页面内容；Component、ListItem 和导入工具的 Overlay 分类不是新增的排序层。需要点击关闭或操作的通知不是 Toast，应按模态程度选择 Panel 或 Popup。
- 页面内的背景、装饰和列表留在页面子树；只有需要跨页面呈现的动画才进入 Effects。视图不能因为创建较晚或想显示在前方而临时升层。
- 同层局部顺序由该层的宿主或导航所有者管理；弹窗使用显式栈。移动宿主或内容的 sibling index 不得改变跨层顺序。

## 分层根与 Canvas 所有权

分层根统一拥有语义宿主、层根 Canvas 的排序、渲染域、相机绑定和层间输入门控。页面/导航所有者负责页面显示和页面历史；内容创建者负责自己的实例生命周期。

1. 每个宿主有明确引用、唯一语义标识和 CanvasGroup 输入边界。缺失、重复或位于错误根下的绑定在初始化时明确失败，不临时创建另一套 UI 根作为兜底。
2. 每层可有一个或多个由分层根登记的根 Canvas；Pages 可由各完整页面提供根 Canvas 和独立 CanvasScaler。页面缩放、参考分辨率与 Safe Area 策略由消费项目选择。
3. 挂入内容时，由分层根将子 Canvas 纳入目标层，禁用其独立 `overrideSorting`，统一所属渲染与排序域。内容不能新增独立根 Canvas、改 sortingLayer/order、换相机或用独立渲染模式逃离语义宿主。
4. 分层排序只对同一渲染域作保证。项目应统一 Screen Space 的相机/渲染策略；World Space UI、多相机与独立显示目标需要单独的组合策略和验收，不能仅比较 sortingOrder 数值。
5. 子 CanvasGroup 不得通过 `ignoreParentGroups` 绕过父层或栈顶门控。Effects、Toasts 的后代也必须遵守其非交互边界。
6. 分层规范化只修改规范拥有的层级、排序与输入边界字段，不重写按钮图片 fitting、文字、几何、美术或场景实例覆盖。资产变更通过 Unity Editor API 完成。

## 挂载与生命周期契约

消费项目应提供等价于“取语义宿主、挂入内容、登记/释放输入门控”的能力，方法与类型名称由项目实现。挂载不替代导航，也不自动加载、暂停玩法或管理存档。

- 新视图的 Feature Spec 先记录：语义层、实际宿主、直接引用或加载键、创建者、显示/隐藏/销毁所有者、模态打开模式、输入门控所有者与失败恢复。
- 创建者先验证宿主、资源和必要组件，完成初始化后再公布实例、更新当前导航或门控。失败时清理本次临时内容，保留已有窗口、栈、焦点和业务状态。
- 路径加载与资源目录遵循 [ResourceLoading.md](ResourceLoading.md)。弹窗首次使用时加载，默认关闭后隐藏并复用；一个宿主生命周期内，同一加载键不重复创建缓存实例或订阅。
- 宿主销毁时由所有者关闭内容、释放门控和订阅、销毁所拥有的缓存实例。跨场景常驻宿主必须单独说明生命周期；不能把场景引用留给常驻缓存。
- 隐藏与释放资源不同。关闭弹窗不调用全局卸载，不卸载仍被其他页面引用的共享图集、材质或字体。

## 模态打开、关闭与返回

模态导航区分以下两种行为；每个入口在规范中明确选择，不能用“打开弹窗”隐含两种语义。

| 模式 | 打开后的行为 | 关闭后的行为 |
| --- | --- | --- |
| Replace | 新窗口准备成功后替换当前窗口序列；旧窗口退出当前栈 | 返回窗口外的既有页面/内容，不自动恢复被替换的窗口 |
| Stack | 保留下层窗口的显示和状态，将新窗口置于栈顶 | 仅关闭栈顶，恢复仍在栈中的前一个窗口输入 |

- 同一缓存窗口不能出现重复栈项；再次 Stack 打开时将已有项移到栈顶。
- 只有栈顶窗口接受按钮、关闭、返回键等输入；隐藏、禁用或被覆盖窗口的回调也必须检查输入资格。
- 关闭请求交给栈所有者，不直接销毁缓存实例。关闭栈顶不会清空下层；显式 Clear 才清空整个窗口序列。
- 加载失败、组件不匹配或初始化异常不能先关闭当前窗口或先改变门控。记录可定位的加载键，通过现有提示机制说明失败，修复资源后允许重试。
- 导航离开或宿主销毁时如何 Clear，由项目导航所有者明确执行。队列 Queue、全局页面历史、多实例弹窗是独立扩展，不能由本契约或其他 Router 的枚举推断为已支持。
- 栈为空只表示弹窗不再提供门控；不能因此解除其他 Guide/Blocker 门控或直接恢复玩法。

## 输入门控与玩法边界

绘制在前面、禁止低层输入、暂停玩法是三项独立决策。

- 每个模态拥有者登记自己的门控。以所有有效门控中的最高层为门槛：低于门槛的层关闭 `interactable` 和 `blocksRaycasts`，门槛所在层及更高层仍按自身规则接收输入；Effects、Toasts 始终关闭输入。
- 同层窗口之间的输入由弹窗栈单独控制，不能依靠层门槛区分栈顶和下层。
- 相同拥有者重复登记/释放应幂等；一个拥有者默认占一个门控项。需要独立释放的多个阻断使用不同拥有者或令牌。关闭、取消、失败和销毁路径都释放自己登记的项，不能直接把所有低层重新设为可交互。
- Guides 不因显示就自动阻断输入；需要模态引导时显式登记，若允许点击指定目标，由项目引导逻辑明确转发/授权，不能靠忽略父 CanvasGroup 穿透。
- 全屏阻断同时提供门控与覆盖屏幕的射线目标。透明背景或 CanvasGroup 本身不能替代完整的交互与生命周期设计。
- 该门控只覆盖 uGUI。键盘、手柄、返回键和世界点击需要各自的项目输入入口遵守当前模态；具体玩法暂停、继续和时间缩放通过项目 Command/System 决定。UI 基础设施不直接修改 Model、扣费、切关或设置玩法时间。

## 最小验收矩阵

每个采用本规范的项目验证自己的实现；文档存在不代表运行行为通过。

| 边界 | 必须证明的结果 |
| --- | --- |
| 绑定与顺序 | 七层引用完整、顺序单调；缺失/重复绑定明确失败 |
| 排序隔离 | 晚创建、调整 sibling、带高排序子 Canvas 的 Panel 始终在 Popup 下方 |
| 栈与输入 | Replace/Stack 区别正确；只命中栈顶，重复打开不重复入栈，关闭后恢复正确来源 |
| 门控组合 | Popup 与 Guide/Blocker 同时存在时，释放其中一个不会解除另一个；Effects/Toasts 后代不能抢输入 |
| 失败与恢复 | 缺失资源/错误组件/初始化失败保留当前窗口、门控和业务状态；清理失败实例后可重试 |
| 生命周期 | 关闭重开复用；离开/销毁后无残留实例、订阅或门控；异步请求在宿主失效后不发布内容 |
| 射线与布局 | 至少经过一帧真实渲染后验证命中；检查目标分辨率、Safe Area 和手工配置保留 |
| 性能与业务 | 无逐帧层级扫描/重复依赖查找；暂停、继续及其他业务仍由项目负责 |

只对改动涉及的边界执行必要验证。规范或文档修改不冒充新的运行时、设备或第二项目验证。

## 跨项目分发与演进

- 复用本文及验收矩阵，每个消费项目另写接入映射，列出根节点、接口、生命周期、输入入口和项目策略。Setup 提供项目接入模板，不能将尚未填写的映射视为运行验收。
- 回提 Foundation 时，通用文档放在仓库 `Docs/UiLayers.md`，由 Setup 同步为消费项目 `Docs/Foundation/UiLayers.md`；同步消费项目 AGENTS、UI 相关 Skills、Feature Spec 模板和治理模板。项目接入映射保留为项目自有文件。
- 先复用规范和示例；运行时代码在至少两个项目证明需要相同替换边界后再抽取，不能把消费项目的 Game 类型、页面、经济、暂停策略、相机或分辨率常量带入公共包。边界见 [Architecture.md](Architecture.md)。
- 版本 1 固定七层语义、相对顺序、排序所有权、栈和门控契约。改变这些行为需要显式迁移与验收；仅更换项目接口名或展示配置不改变契约版本。
